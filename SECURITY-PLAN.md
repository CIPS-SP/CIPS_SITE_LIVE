# Security review: plan (started 7 Nov 2026)

HANDOVER.md open job 13. Scope: the public website (`site/`, Cloudflare Pages), the drop box (`review-drop-box/`, Cloudflare Worker) and the accounts and email set-up around them. Not in scope: the Desk (its own project on Render) and Howard's lab.

## Tests on the live enquiry route (7 Nov 2026, before the site's form uses it)
**One failed, now fixed in the code (fix now):** in the email Simon received, `<b>` typed into the form showed as bold and `<a href>` as a working link. The box sent plain text only and Brevo built an HTML version from it without escaping, so a visitor could put a disguised link or a remote image into the duty agent's inbox. Fix: the box now sends its own HTML version with every character of the visitor's text escaped (`htmlContent` in `src/enquiry.js`, with a test). Deployed 7 Nov; the repeated test (E-5BHNHK, 18:01) showed every tag as plain characters. Outlook still underlines bare addresses itself, which is harmless (what you see is where it goes).

Seen in that email, for later:
- **Outlook says "We could not verify the identity of the sender"** and shows it as admin@cips.agency "via ...brevosend.com": expected, since cips.agency is not authenticated in Brevo. Staff should know these website emails carry that warning, and that a real-looking CIPS email with that warning from anywhere else is suspicious.
- **DMARC will catch these emails (important for C12).** They claim to be from admin@cips.agency but are sent by Brevo, so once DMARC is tightened to quarantine or reject, Microsoft 365 would junk or refuse them. Before tightening, either change `MAIL_FROM` to an address on a domain that is not cips.agency (verified in Brevo), or add an Exchange rule that lets Brevo's emails to dutyagent@ through. `p=none` (report only) is safe.
- **Outlook blocked a picture**: the box's email contains none, so it is Brevo's open-tracking pixel. Brevo does not let free accounts switch tracking off for transactional email (on request, Enterprise only, per Brevo staff on its forum). Accepted (Simon, 7 Nov): click tracking has nothing to track since the escaping fix (no real links), the pixel only tells Brevo when CIPS opens the email (visitors are never tracked), and Outlook blocks it unless someone clicks "download pictures" on these emails. Note.

The rest passed against https://cips-review-drop-box.simon-92c.workers.dev:
- Refused, nothing saved: another website (403; its browser pre-check gets no permission), a body over 16 KB (413), not JSON or not a form (400), a missing name (400), a made-up topic (400), GET on the route (404).
- Robots: the trap field filled, or the form sent in under 2.5 s, gets a fake thank-you and reference; nothing is kept or emailed.
- The enquiry list without the Desk password, or with a wrong one: 401. Fake Brevo delivery reports without the password, or with a wrong one: 401.
- Rate limit: the 6th enquiry in an hour from one address is refused (429); the page then offers the email-app route.
- A fake "Bcc:" line in the name and contact, and a message over 4,000 characters: the extra lines folded into one (nobody copied in), the message cut at 4,000, and no Reply-To (the contact no longer looks like an address). (Code in the message: see the failure above.)
- Real enquiries: two delivered to dutyagent@ and marked delivered by Brevo's reports.

Notes from the tests (for B6):
- A request with no Origin at all (a script, not a browser) is accepted like the form; only the rate limits and the daily cap stop a script. That is normal for a public form.
- Each enquiry costs about 8 KV writes (two counters, the item, the pending mark, the send counter, the sent and delivered updates, the message id). At the 150-a-day cap that is about 1,200, above the free plan's 1,000 writes a day: a flood that fills the cap could also stop reviews being saved for the rest of the day. Fix with B6 (a Cloudflare rate-limit rule) or a lower daily cap.

## B5, B6, B8, B9 (7 Nov 2026; drop box deployed 23:21 and checked live: refusals all pass, reviews load, a made-up code gets 404, a real enquiry (E-63VSJJ) delivered)
- **B9 tools:** `npm audit`: 0 known vulnerabilities. Wrangler is only used to deploy; the running drop box has no outside code at all.
- **B5 read-through** of `src/worker.js` and `src/enquiry.js`. Good: secrets and the webhook token compared in constant time; only the listed websites get browser permission (CORS); every field checked and capped; errors say little; Desk-only routes need the password; the review queue and enquiries expire. **Fixed:** the short address fingerprint used for rate limits was a plain hash, which can be reversed by trying every address; it is now mixed with a secret. **Noted, accepted:** a request with no Origin (a script) is treated like the form, so the rate limits are the real defence; the counters are approximate (storage is not atomic), fine for stopping floods; a body sent without a length is read before the 16 KB check (Cloudflare caps it; low risk).
- **B6 flood resistance (fixed in code):** a Cloudflare rate-limiting rule is not possible: those rules work on a domain run through Cloudflare, and the drop box is on workers.dev (moving cips.agency's DNS to Cloudflare is ruled out). So the box now protects its own write budget: the enquiry day cap is checked by **reading only** before anything is written, so once full, a flood from new addresses costs nothing; the cap is **60 enquiries a day** (was 150; above it the page offers the email-app route); made-up review codes are recorded only up to **100 a day**, after that refused without writing (real codes still work). Worst case is now well under the free plan's ~1,000 writes a day. Tests prove both. **Accepted:** the free plan's 100,000 requests a day for the whole box; a flood big enough to use those would stop reviews and enquiries for the rest of that day (the enquiry form then offers the email-app route).
- **B8 bot check:** recommendation: keep the trap field, the 2.5-second timing check and the rate limits; no Cloudflare Turnstile (it loads a script from Cloudflare, breaking the site's nothing-from-outside rule, and adds a puzzle for real visitors). Revisit if spam enquiries start arriving. **Closed for now (Simon, 7 Nov 2026): see how it goes, revisit if spam arrives.**

## The plan

### A. The website (Claude, on `dev`, checked locally before any release)
1. **Security headers** in `site/_headers`: frame protection (`frame-ancestors 'none'` / `X-Frame-Options: DENY`), `Permissions-Policy` (no camera, microphone, location, payment), and a **Content-Security-Policy** that allows only our own files and the drop box. The CSP needs care: the pages use inline scripts and the globe uses WebGL, so it is built and tested page by page with the full check (`node check.mjs`) before it goes live. HSTS added when cips.agency is connected.
2. **Anything that puts text into a page** (`innerHTML`): list every place, confirm what reaches it is escaped or our own.
3. **What is public**: confirm nothing in `site/` that should not be (notes, old files, internal addresses, personal data); links that open a new tab carry `rel="noopener"`.
4. **The preview log-in page**: a page asking for a password that goes nowhere can teach people to type real passwords into it. Decide: hide the header's "Log in" link until log-in is real, or keep it with the clear "preview" line.

### B. The drop box (Claude, tests first; redeploying needs Simon's OK)
5. **Read-through of `src/worker.js` and `src/enquiry.js`** for anything that can be abused: sizes, field checks, CORS, password and token checks, error messages that say too much.
6. **Flood resistance.** Cloudflare's free plan allows about 1,000 KV writes a day; a determined flood of fake reviews or enquiries could use them up and stop real ones for the rest of the day. Measure how many writes each request costs, and consider a Cloudflare rate-limiting rule on `/api/*` (one is free) in front of the box.
7. **Secrets**: where each one lives (Cloudflare, Render, Brevo), who can see them, how to replace one quickly; Wrangler signed out after every deploy (`npx.cmd wrangler logout`) **and** revoked in the Cloudflare dashboard under Profile → Access Management → Connected Applications: logging out alone left Wrangler listed there with 29 permissions (found 7 Nov; Simon revoked it).
8. **Bot check**: Cloudflare Turnstile would stop more robots but loads a script from Cloudflare, which breaks the site's "nothing from outside" rule. Decide whether to keep relying on the trap field, timing and rate limits.
9. **Tools**: `npm audit` on the drop box's one tool (Wrangler, used only to deploy).

### C. Accounts and email (Simon, with a checklist from Claude): the biggest real-world risks
10. **Two-step sign-in (2FA)** on every account that can change the site or read its data: GitHub, Cloudflare, GoDaddy, Brevo, Airtable, Render, Microsoft 365. Check who has access to each and remove anyone who no longer needs it.
11. **GoDaddy domain lock** (transfer lock) on cips.agency, and a check of who can edit its DNS.
12. **Stopping fake CIPS emails.** Without DMARC, anyone can send email that claims to be from cips.agency; for a port agency the danger is fake invoices or bank details sent to clients. Add a DMARC record in GoDaddy on its own (not Brevo's): report-only first (`p=none`, reports to an address of CIPS's), then quarantine after a few weeks of clean reports, **but first deal with the website's enquiry emails** (sent by Brevo as admin@cips.agency, they would fail DMARC: see the tests above). Check at the same time that the SPF record covers Microsoft 365's outgoing mail. (Brevo is deliberately not authenticated for cips.agency, Simon 7 Nov, so Brevo can never send as CIPS.)

### D. When cips.agency goes public
13. (Not security, but before go-live: the full phone review, HANDOVER.md open job 17.) HSTS, the custom domain on the Pages project, security.txt's Policy address, removing `noindex` for cips.agency only, the drop box's allowed addresses and `REVIEW_PAGE`.

### E. If something goes wrong
14. A one-page "what to do" note: a leaked key (replace it in Cloudflare and Brevo), the site changed by someone else (roll back on Cloudflare Pages), a personal-data breach (Jersey law: tell the JOIC within 72 hours if it is a risk to people; keep a record either way).
